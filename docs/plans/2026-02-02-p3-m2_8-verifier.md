# Verification Pipeline Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Implement a low-coupling, production-grade verification worker that runs toolbelt scripts, writes evidence artifacts/events, and gates outputs with strict/balanced modes.

**Architecture:** Add a verification module and worker that accept task-frame + claims + pointers, run toolbelt scripts via PythonTool, and write `verification.input.json`, `verification.report.json` (SSOT), and `verification.report.view.md` as evidence artifacts. Emit verification events with summary-only payloads and strict event closure. Retrieval is injected as an optional capability.

**Tech Stack:** TypeScript, Zod, EvidenceWriter, PythonTool, Bun tests.

## Definition of Done (DoD)
- **Protocol:** `verificationId` UUID per run; report schema with stable ordering rules; any unknown/unsupported must be explicit with Chinese reasons.
- **Events:** `verification.requested` → (completed | degraded | timeout | cancelled); event payload contains **summary + artifact pointers only** (no big arrays); degraded must include Chinese hint.
- **Artifacts:** Always write `verification.input.json`, `verification.report.json` (SSOT), `verification.report.view.md` (human view). Must be evidence artifacts.
- **Semantics:** `ok` means validated within capability boundaries; `degraded` means capability missing/inputs insufficient. Balanced without retrieval must state “未启用补检索，仅对现有证据做静态校验”.
- **Budgets:** support `budget.timeMs` and optional limits; timeout/cancel must emit final event and partial report with `incomplete=true`.
- **Determinism:** tool order fixed (citation-check → doc-quote-anchor/table-check → redaction-scan). `claims[]/evidence[]/reasons[]` must be stable (keep input order or explicit sort).
- **Tests:** real Python toolbelt scripts (no mocks), packages/opencode bun test only.
