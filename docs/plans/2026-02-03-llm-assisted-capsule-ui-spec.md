# LLM-assisted Capsule UI/UX Specification (v1.0)

> **版本**：1.0
> **日期**：2026-02-03
> **作者**：Gemini (UI/UX Agent)
> **状态**：Draft
> **关联文档**：`docs/plans/2026-02-03-llm-assisted-capsule-design.md`

本文档定义了 **LLM-assisted Capsule（AI 建议要点）** 的用户界面规范、交互逻辑与中文文案标准。目标是确保用户明确感知到“这是 AI 的建议（非事实记录）”，并能通过“引用核验”机制安全地使用这些信息。

---

## 1. UI 入口与交互形态

### 1.1 Activity 流入口

在 Activity 列表中，该胶囊表现为一个 **系统级事件卡片**，位置通常出现在 `compaction.completed` 之后。

- **组件**：Activity Item (Standard)
- **视觉风格**：
  - **图标**：`Sparkles` (HeroIcons) 或 `Lightbulb` (暗示智能/建议)
  - **颜色**：
    - 成功：`purple` (区分于常规 System 的 gray/blue，暗示 AI/Magic)
    - 降级：`amber` (Warning)
    - 失败：`red` (Error)
- **点击行为**：打开 **"AI 建议详情面板"** (Drawer/Slide-over)，展示完整清单与引用。

### 1.2 状态形态 (Activity Narrative)

参照 `activity-narrative.ts` 的叙事风格：

| 状态         | 标题 (TitleZh)            | 副标题 (SubtitleZh)          | Badge  | Severity | 交互       |
| :----------- | :------------------------ | :--------------------------- | :----- | :------- | :--------- |
| **Running**  | 正在生成建议要点…         | 分析上下文与证据链           | 进行中 | info     | 禁用       |
| **Success**  | **AI 建议要点（可核验）** | 包含 N 个决策 · M 个待确认项 | 建议   | success  | **可点击** |
| **Degraded** | **AI 建议要点（已降级）** | 部分引用无法核验/内容受限    | 降级   | warning  | **可点击** |
| **Failed**   | 生成建议要点失败          | [具体原因，如：预算超限]     | 失败   | error    | 查看日志   |

> **设计意图**：标题强制带“（可核验）”后缀，从入口处即建立“需核实”的心理预期。

## 2. 详情面板 (Detail Panel) 设计

点击 Activity 卡片后弹出的详情层。

### 2.1 头部 (Header)

- **标题**：AI 建议要点
- **标签**：`Experimental` (Beta 阶段)
- **操作区**：
  - `[复制要点]` (Button)：将内容格式化为 Markdown 复制到剪贴板（用于粘贴到 Issue/PR）。
  - `[关闭]` (Icon Button)

### 2.2 信息层级 (Body)

内容区域分为两栏或上下两块，严格区分“已决”与“未决”。

#### A 区：已形成的决策 (Decisions)

- **Section Title**：✅ 已形成的决策 (Decisions)
- **列表项样式**：
  - **文本**：主色 (`text-foreground`)，字号正常。
  - **引用标记**：在文本末尾跟随 `[Ref]` 胶囊按钮。
    - 样式：`text-xs bg-muted hover:bg-muted-foreground/20 rounded px-1.5 py-0.5 transition-colors`
    - 文案：`#1`, `#2` (对应证据序号) 或 `引用`。
    - **交互**：点击展开/弹出该条目的“证据详情卡片”。

#### B 区：仍待确认的问题 (Open Questions)

- **Section Title**：❓ 仍待确认的问题 (Open Questions)
- **列表项样式**：同上。

#### C 区：未知/需人工确认 (Unknowns)

_当某条目状态为 `unknown` 时，不应直接丢弃，而是归类展示（或在原列表中高亮标记）。_

- **样式**：带有 `amber` 色背景/边框的警告块。
- **文案格式**：
  > [文本内容]
  > ⚠️ **需确认**：[unknownReasonZh]
- **折叠策略**：如果 Unknown 条目超过 3 条，默认折叠，显示“展开另外 N 条待确认项”。

### 2.3 底部 (Footer) / 元信息

- **模型信息**：`Generated by [ModelName] · [Latency]ms`
- **核验状态**：
  - ✅ 引用链完整 (All refs resolved)
  - ⚠️ 存在断链 (若发生降级)

## 3. 引用展示与交互 (Evidence/Citation)

当用户点击条目旁的引用标记（如 `[#1]`）时，展示证据详情。

### 3.1 证据详情卡片 (Popover/Expandable)

- **标题**：证据来源
- **内容**：
  - **文件路径**：`path` (支持截断，如 `.../packages/app/src/utils.ts`)
  - **类型**：`File` | `Event` | `Diff` | `Issue`
  - **版本指纹**：`SHA: ab12cd...` (显示前6位，鼠标悬停显示完整)
  - **相关度/锚点**：`Lines: 10-15` (如果有 anchor)
- **操作**：
  - `[打开文件]`：跳转到编辑器/文件浏览器的对应位置。
  - `[复制路径]`

### 3.2 引用截断规则

- **Path**：保留文件名，保留最近一级目录。长路径使用 `...` 省略中间部分。
  - 例：`/Users/.../src/components/Button.tsx`
- **Ref ID**：不直接向用户展示冗长的 Ref String，仅在 UI 上使用数字索引 `1, 2, 3...` 对应本面板内的引用列表。

## 4. 关键中文文案 (Copywriting)

### 4.1 状态与提示

| Key                      | 中文文案              | 备注                        |
| :----------------------- | :-------------------- | :-------------------------- |
| `title`                  | AI 建议要点（可核验） | 强调可核验性                |
| `status_degraded`        | 已降级                | Warning 状态                |
| `degraded_reason_prefix` | 原因：                | 用于拼接后端返回的 reasonZh |
| `btn_copy`               | 复制要点              | Action                      |
| `section_decisions`      | 已形成的决策          | Header                      |
| `section_questions`      | 仍待确认的问题        | Header                      |
| `label_evidence`         | 证据引用              | Tooltip/Heading             |
| `unknown_badge`          | 需确认                | Badge                       |
| `unknown_prefix`         | 无法核验：            | 用于 unknownReasonZh 前     |

### 4.2 降级原因 (Degraded Reasons) 映射

| Reason Code        | 用户友好的中文解释           |
| :----------------- | :--------------------------- |
| `schema_invalid`   | 数据格式异常                 |
| `ref_unresolvable` | 引用无法解析（证据丢失）     |
| `sha_mismatch`     | 文件版本不一致（内容已变动） |
| `budget_exceeded`  | 内容过长，已截断             |
| `content_unsafe`   | 内容包含敏感/不安全格式      |
| `timeout`          | 生成超时                     |

## 5. “复制要点”产物格式

当用户点击“复制要点”时，生成如下 Markdown 文本：

```markdown
## AI 建议要点 (2026-02-03)

### ✅ 已形成的决策

- 决定采用 Shadcn UI 作为组件库基础 (引用: package.json)
- 将 API 请求超时设置为 30s (引用: src/config.ts)

### ❓ 仍待确认的问题

- [ ] 需确认是否需要支持 IE11 (无法核验: 文档未提及浏览器兼容性)
- [ ] 登录接口的具体错误码规范 (引用: docs/api.md, 但内容模糊)

> 由 Opencode AI 生成，请人工核实引用。
```

## 6. 后端字段需求 (Backend Requirements)

UI 渲染所需的最小字段清单 (对应 `Item` 和 `Evidence` 结构)：

1.  **`items` (Array)**: 包含 Decisions 和 OpenQuestions。
    - `text` (string): 显示文本。
    - `type` ("decision" | "question"): 分组依据。
    - `status` ("known" | "unknown"): 样式依据。
    - `unknownReasonZh` (string?): 警告文案。
    - `evidenceIndices` (number[]): 指向 evidence 数组的下标（前端优化，后端传 refs 也可以，但前端需要 mapping）。
2.  **`evidence` (Array)**: 所有的引用池。
    - `path` (string): 显示路径。
    - `kind` (string): 图标依据 (file/issue/etc)。
    - `sha256` (string): 版本显示。
    - `anchor` (string?): 行号/定位信息。
3.  **`meta`**:
    - `isDegraded` (boolean)
    - `degradedReasonZh` (string?)
    - `modelName` (string)
