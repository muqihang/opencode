# I.11 开工前启动门禁清单（p4-2）

- 日期：2026-02-12
- 适用范围：`card-blk-06 / p4-2 / I.11`
- 用途：恢复实施前的一次性门禁检查（go/no-go）

## A. 数据门禁（Data）

- [ ] 输入数据源已锁定，来源与版本可追溯。
- [ ] 基线样本与对照集已冻结，口径文档已评审。
- [ ] 指标定义、计算方式、统计窗口一致且可复现。
- [ ] 数据异常处理策略明确（缺失、脏数据、延迟）。

阻塞条件（任一命中即阻塞）：
- 数据来源不稳定或不可追溯。
- 指标口径在评审中存在冲突且未闭合。

## B. 测试门禁（Test）

- [ ] 最小验收测试集已定义并可执行。
- [ ] 回归测试范围与通过阈值已定义。
- [ ] 失败分级与处置 SLA 已明确（谁在何时响应）。
- [ ] 验收结果记录模板已准备。

阻塞条件：
- 无法执行最小验收集。
- 通过/失败标准不明确，无法客观判定。

## C. 回滚门禁（Rollback）

- [ ] 回滚触发阈值已量化（错误率、时延、可用性等）。
- [ ] 回滚脚本/步骤已演练，预计耗时在窗口内。
- [ ] 回滚后验证项已定义（健康检查、关键指标恢复）。
- [ ] 值班与升级路径（oncall/escalation）已确认。

阻塞条件：
- 回滚步骤未演练或演练失败。
- 回滚后无法在可接受时间内完成验证。

## D. 资源门禁（Resource）

- [ ] 研发 owner、测试 owner、发布 owner 全部到位。
- [ ] 实施窗口与保障窗口已确认（含备选窗口）。
- [ ] 关键依赖方（上游/下游）已确认可配合。
- [ ] 资源冲突已评估并完成优先级裁决。

阻塞条件：
- 任一关键角色缺位或不可到场。
- 关键依赖未确认，存在不可控外部阻塞。

## E. 评审门禁（Review）

- [ ] 产品、研发、测试、运维联合评审已完成。
- [ ] 风险清单、缓解措施、责任人已逐项确认。
- [ ] 遗留问题有明确 owner 与关闭时间。
- [ ] 评审结论与证据链接已归档。

阻塞条件：
- 评审结论为“有条件通过”但条件未闭合。
- 高风险项无 owner 或无明确截止时间。

## F. 通过/阻塞判定规则（Go/No-Go）

通过（GO）规则：
1. A~E 五类门禁所有必选项均勾选完成；
2. 所有阻塞条件均未命中；
3. 评审结论为“通过”，且记录已归档。

阻塞（NO-GO）规则：
1. 任一门禁项未满足且无书面豁免；或
2. 任一阻塞条件命中；或
3. 回滚口径未量化/未演练。

执行规则：
- 判定结果必须以会议纪要 + 责任人签字（电子可）落档。
- 仅允许在“GO”结论下启动 I.11 实施。
- 若为“NO-GO”，必须回到 deferred 状态并重新排期。
