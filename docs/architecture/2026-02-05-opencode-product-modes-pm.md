# OpenCode「产品模式」说明（给 PM / 业务同学）

这份文档用“人话”解释：OpenCode 的 **模式开关** 是什么、用户怎么切、切完会发生什么、以及插件没装/还没做时会怎样。

## 1. 我们为什么需要“模式”

OpenCode 既可以“只用基座能力”完成任务，也可以通过插件（例如 `oh-my-opencode`）把派工/验收等能力升级为“团队式多会话协作”。

但商业化产品里最怕的是：

- 基座和插件 **同时** 在派工，用户会感觉混乱（提示多、权限弹窗多、审计链路也不清晰）。
- 用户不知道什么时候该开插件、什么时候该关插件。

所以我们把它做成一个 **一键模式开关**：用户只需要选一个模式，系统就会自动按模式决定哪些插件加载、以及基座在需要派工时该怎么做。

## 2. 四种模式分别是什么

> 这些模式都是“产品层”的开关，不是模型参数；你可以把它理解为“启用哪套行业插件 + 派工策略”。

### 2.1 基础模式（base）

- **不启用行业插件**（默认 allowlist 为空）
- 基座负责对话与派工（符合“装上就能用”的预期）

适用：日常通用问答、简单任务、只想用 OpenCode 原生能力。

### 2.2 编程开发模式（programming）

- 默认只启用 `oh-my-opencode`
- 多会话派工默认由插件接管（基座默认只“提示式派工”，避免重复派工）

适用：软件开发、代码审查、需要并行子任务拆解的工作流。

### 2.3 律师助理模式（legal）

- 默认只启用律师类插件（例如未来的 `oh-my-legal`）
- 多会话派工默认由插件接管（基座默认只“提示式派工”）

适用：合同审阅、法律检索、条款比对、证据整理等。

### 2.4 马哲分析模式（marxism）

- 默认只启用马哲分析插件（未来例如 `oh-my-marxism`）
- 多会话派工默认由插件接管（基座默认只“提示式派工”）

适用：马列哲学/政治经济学相关的结构化分析（插件能力到位后体验最佳）。

## 3. 用户怎么切换模式（GUI / TUI / 配置）

### 3.1 GUI（Desktop）

在 OpenCode Desktop 里：

1) 打开任意一个工作区（Workspace）  
2) 进入 Settings  
3) 找到 **Mode（模式）**  
4) 选择：基础 / 编程 / 律师 / 马哲分析

切换后会触发一次“实例重新加载”（reload），以确保插件真正被加载/卸载。

### 3.2 TUI（终端界面）

TUI 内有“模式选择”对话框，选择后会写入同一份配置，并触发 reload。

### 3.3 直接改配置文件（高级用法）

模式本质是一个配置字段：

```jsonc
{
  "product": {
    "mode": "programming"
  }
}
```

如果你想精确控制每个模式启用哪些插件，也可以配置：

```jsonc
{
  "product": {
    "mode": "legal",
    "plugins": {
      "common": ["some-plugin-you-always-want"],
      "legal": ["oh-my-legal"]
    }
  }
}
```

## 4. 切换后会发生什么

模式切换会带来两个“肉眼可见”的变化：

1) **插件加载变化**  
   只有被 allowlist 点名的插件会被加载；其他插件即使被发现，也不会启用。

2) **派工策略变化**  
   - `base`：基座可以按默认策略自动派工
   - 非 `base`（programming / legal / marxism）：默认更偏“提示式派工”，避免和行业插件抢派工权

## 5. 插件没装/插件还没实现，会不会炸？

不会。

- 用户选了某个模式，但对应插件没装：OpenCode **不会报错**，只是该插件不会被加载（效果相当于“没启用插件”）。
- 这保证了：我们可以先把“模式开关”做成产品能力，插件可以分期上线。

## 6. 怎么回到基础模式

在 GUI / TUI 里把模式切回 **基础模式（base）** 即可。

如果你想完全回到“未设置 `product.mode` 的旧行为”，可以手动在配置里移除 `product.mode` 字段（这是高级用法；一般不需要）。
